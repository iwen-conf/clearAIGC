# Claude 解决 AI 率优化问题的思路

> 本文档是 `00-ai-rate-two-pass-issues.md` 的解决方案篇。目标是给出工业级可落地的方案,把"AI 率"从展示指标改造成**可被真实优化的目标函数**,并让整条流水线以"降分"为导向闭环运行。

---

## 1. 问题重定义

当前现象是"优化后 AI 率从 28% 升到 72%"。根因不是算错,而是**三个层面同时错位**:

| 层面       | 当前状态                                 | 工业级应是                                     |
| ---------- | ---------------------------------------- | ---------------------------------------------- |
| 度量       | 启发式规则打分,与真实检测器零相关        | 多检测器融合,校准到可信真分布                  |
| 优化目标   | 不存在目标函数,rewriter 不看 AI 率       | 以 AI 率、语义保真、可读性为复合损失           |
| 反馈       | 跑 2 轮,无收益判断,无句级粒度           | 句级 Best-of-N + 门控 + 回退,按需停止          |

解决方案必须同时动这三层,任何只动一层的改动都会被另外两层拖回原地。

---

## 2. 设计原则

1. **可信比便宜重要**:检测信号必须能对齐真实检测器,否则一切优化都是自欺。
2. **目标函数单一化**:把"降 AI 率、保语义、保可读"压成一个复合分,流水线只优化它。
3. **句级而非整篇**:AI 特征高度局部化,整篇重写会破坏保真,必须定位到句。
4. **闭环而非固定轮次**:每次改写都要能回答"比上一版好吗?";不好就回退,足够好就停。
5. **失败透明**:降不下来时明确告诉用户,不要假装成功。

---

## 3. 总体架构

```
┌─────────────┐   ┌─────────────┐   ┌─────────────────────┐   ┌─────────────┐
│  Parse/Chunk│ → │ AI-Scorer   │ → │  Targeted Rewriter  │ → │  Validator  │
│  (已有)     │   │ (新)        │   │  (改写层重构)       │   │  (扩展)     │
└─────────────┘   └─────────────┘   └─────────────────────┘   └─────────────┘
                         ▲                    │                      │
                         │                    ▼                      │
                  ┌──────┴──────┐     ┌───────────────┐        ┌─────▼──────┐
                  │ Calibrator  │     │ Best-of-N     │        │ Fidelity   │
                  │ (校准层)    │     │ Candidate Gen │        │ Gate       │
                  └─────────────┘     └───────────────┘        └────────────┘
                         ▲                                            │
                         │                                            │
                  ┌──────┴──────────────────────────────────────┐     │
                  │  Decision Loop: accept / reroll / fallback  │◀────┘
                  └─────────────────────────────────────────────┘
```

五层分工:

- **Scorer**:估计每句/每段的 AI 分,给出可解释的细分信号(困惑度、突发性、n-gram 异常度、套话密度)。
- **Calibrator**:把内部分数线性/等距校准到至少一个真实检测器分布上,周期性重标定。
- **Targeted Rewriter**:只针对高分句子做改写,接收"目标降分区间"作为 prompt 约束。
- **Validator**:对改写后文本做保真度 + 可读性 + AI 分复测,给出接受/拒绝/重试决策。
- **Decision Loop**:Best-of-N 采样,挑选 Pareto 最优解;达不到门槛则整句回退。

## 4. 评分层:从启发式到真实信号

### 4.1 信号集合(四路并行)

| 信号         | 含义                                    | 实现                                                                                       | 成本 |
| ------------ | --------------------------------------- | ------------------------------------------------------------------------------------------ | ---- |
| Perplexity   | 局部 token 概率平均值,AI 文本偏低       | 本地小模型(Qwen2.5-0.5B 或 GPT2-zh)逐 token 算 `-log p`;滑动窗口均值          | 低   |
| Burstiness   | 句长与 PPL 在句间的方差                 | `var(sentence_ppl)` + `var(sentence_length)`,归一化                                        | 低   |
| n-gram 异常  | 特定高频 AI token 组合命中率            | 维护可更新词表(基于公开 AI 语料 + 自家回流样本),TF-IDF 加权                             | 低   |
| 外部检测器   | GPTZero/Originality/Sapling/ZeroGPT API | 抽样调用,缓存 24h;仅用于校准与高价值样本                                                 | 高   |

最终分数:

```
ai_score = w1*norm(1/PPL) + w2*(1-norm(Burstiness)) + w3*ngram_score + w4*external_score
```

权重 `w1..w4` 初始均值 0.25,通过校准器在标注集上拟合。阈值(绿/黄/红)也按校准后分布切分位(p33、p66),**不再硬编码 33%/66% 百分比**。

### 4.2 校准器(Calibrator)

- 维护一份 **300~1000 条样本的标注集**:一半人写、一半 AI 写、一半润色后。
- 每条样本同时记录:内部分数、各路子信号、真实检测器分数。
- 通过**保序回归(isotonic regression)** 把内部分数单调映射到真实检测器分布。
- 监控指标:**Spearman 秩相关 ≥ 0.7** 才算合格。低于阈值触发告警,禁止对外展示分数。

### 4.3 对当前代码的改造

- `internal/domain/airate.go`:保留启发式作为**最快兜底信号**,但降级为 `ngram_score` 的其中一部分。
- 新增 `internal/domain/scorer/` 包:
  - `scorer.go` 接口:`Score(ctx, text) (AIScore, error)`
  - `perplexity.go` 调本地小模型
  - `burstiness.go` 纯统计
  - `ngram.go` 迁移现有 `aiTransitionPhrases` / `aiAbstractTerms`,加版本号
  - `external.go` 封装检测器 API(支持 GPTZero/Sapling,带速率限制与缓存)
  - `calibrator.go` 保序回归 + 阈值映射,状态持久化到 `var/data/calibration/`
- 前端 `card-review-panel.tsx`:分数字段由单值改为**四路雷达图 + 校准后总分**,同时显式标注"参考检测器:xxx,相关性 r=0.xx"。

## 5. 目标驱动改写层

### 5.1 损失函数

对一段文本 `t`,改写目标是在约束下最小化:

```
L(t') = α · ai_score(t')                  # 降 AI 率
      + β · (1 - sim(t, t'))              # 语义保真(SimCSE / bge-m3 cos)
      + γ · readability_penalty(t')       # 可读性(句长方差不能过大)
      + δ · fact_violation(t, t')         # 实体/数字/引用破坏惩罚(硬约束)
```

默认 `α=0.55, β=0.30, γ=0.10, δ=大(≥10)`。`δ` 压成硬约束是为了防止为降分而瞎改事实。

### 5.2 句级定位

用 Scorer 逐句打分,取前 **top-K 高分句**(K = ceil(句数 × 0.4))作为改写目标。
**其他句子不动**。整篇无差别重写是当前方案的主要错误源之一。

### 5.3 Best-of-N 采样

对每个目标句,在同一 prompt 下用**不同 temperature / top-p / 不同 worker**生成 `N=4` 个候选:

| 候选 | temperature | top-p | worker                     |
| ---- | ----------- | ----- | -------------------------- |
| c1   | 0.6         | 0.9   | lexical_mutator            |
| c2   | 0.9         | 0.95  | syntax_rebuilder           |
| c3   | 0.7         | 0.9   | 混合(先 lex 后 syntax)    |
| c4   | 0.0         | —     | 原句(保底回退选项)       |

对每个候选计算 `L(t')`,选最小者。若最优候选 `L` **没有显著低于 c4(原句)**,则判定"改无可改"→ 保留原句并在报告中标注 `reason=no_improvement`。

### 5.4 Prompt 约束强化

改写 prompt 必须携带:

- 当前句的 AI 分和**命中的具体信号**(例:"这句 PPL=2.1 偏低,命中 4 个 AI 转折词")
- 目标降分区间(例:"把 ai_score 从 0.78 降到 ≤ 0.50")
- **负面词表**(从 `aiTransitionPhrases` / `aiAbstractTerms` 同步,当前 coordinator 提示词里那一段直接用):"不得使用:综合来看、进一步来说、意义、价值、层面、在当前背景下..."
- **人类写作注入规则**:允许轻度口语化、允许一定比例短句、允许破折号/反问/不完美比喻。

### 5.5 与现有 coordinator 关系

- Coordinator ReAct 流程保留,但职责从"重写文本"收窄为"**为每个目标句选择 worker 组合**"。
- 具体改写由 `lexical_mutator` / `syntax_rebuilder` 完成,coordinator 负责 Best-of-N 的候选生成编排。
- 轮次 prompt(`round1_cn.md` / `round2_cn.md`)改为 **worker 级 prompt**,不再作为整篇 prompt 注入。

## 6. 保真度门控(Validator)

任何候选在被接受前必须过三道硬门:

1. **事实不变量**:
   - 数字、日期、百分比、货币:逐字匹配,0 容忍漂移。
   - 命名实体(人名、机构、产品):用 NER(如 hanlp 或本地 LLM)比对,Jaccard ≥ 0.95。
   - 引用/脚注/公式:正则提取后集合相等。
2. **语义相似度**:SimCSE 或 bge-m3 句向量余弦相似度 ≥ 0.80(可配置)。
3. **可读性**:Flesch-Kincaid / 中文可读性(平均句长 + 虚词密度),不得退化超过 15%。

三道门任一不过 → 候选作废,降级到下一名;全部候选都不过 → 保留原句。

这套门控**已经部分存在**于 `internal/workflow/nodes/quality_gate.go`(膨胀比、禁止词、Markdown 注入),扩展即可,不需要新建。

## 7. 决策闭环

替换现有"固定 1/2 轮"为**条件驱动终止**:

```
while True:
    score = scorer(current_text)
    if score.total <= target or rounds >= max_rounds or no_improvement_rounds >= 2:
        break
    targets = top_k_sentences_by_score(current_text)
    for s in targets:
        candidates = best_of_n(s)
        winner = argmin L(c) s.t. fidelity(c) passes
        if L(winner) < L(s) - ε:  # ε = 0.03, 避免抖动
            replace(s, winner)
    rounds += 1
```

参数:

- `target = 0.30`(校准后分数,意即对标真实检测器 AI 概率 ≤ 30%)
- `max_rounds = 3`(上限,不是强制次数)
- `ε = 0.03`(低于这个改动视为噪音,不采纳)
- `no_improvement_rounds = 2`(连续两轮无显著改进 → 停,避免越改越差)

这一改动的直接效果:

- 中文硬编码 2 轮取消,改为**按需 1~3 轮**,多数样本 1 轮即可达标。
- 第二轮"越改越糟"的场景被 `no_improvement_rounds` 与回退机制彻底堵死。

## 9. 验证与持续监控

### 9.1 上线前

- 构建 **500 条回归集**(学术中文 200 + 英文论文 100 + 博客 100 + 已有用户投诉样本 100)。
- 指标门槛:
  - 内部分数 vs 真实检测器(GPTZero/Sapling 任一):Spearman ≥ 0.70
  - 改写后真实检测器 AI 分**平均下降 ≥ 25 个百分点**
  - 语义相似度(SimCSE)均值 ≥ 0.85
  - 事实不变量违规率 = 0
  - 用户感知可读性(抽样人评 5 点量表):均值 ≥ 3.8

### 9.2 上线后

- 每天回流 1% 的真实样本,重跑校准集,检查 Spearman 是否漂移。
- 每周跑一次回归集,指标退化 > 5% 触发回滚。
- Dashboard 面板:`校准相关性 / 平均降分 / 回退率 / 平均轮次数`。

## 10. 成本与性能

| 阶段            | 新增计算                     | 成本估算(相对当前)       |
| --------------- | ---------------------------- | -------------------------- |
| Perplexity      | 本地小模型,CPU 可跑,或 GPU 批量 | 延迟 +30~80ms/句           |
| Burstiness      | 纯 CPU 统计                  | 可忽略                     |
| 外部检测器      | 每日配额 + 24h 缓存          | API 费用 ≈ $0.01~0.03/篇   |
| SimCSE / bge-m3 | 本地向量模型,批量编码        | 延迟 +50ms/段              |
| Best-of-N       | N=4 候选,部分共享前缀         | Token 成本约 2.5x(不是 4x,利用 prefix cache + 只对 top-K 句) |

**综合**:单篇处理成本约为当前 1.8~2.2x,但换来的是**真实降分能力**。多数用户愿意为"真的能降"多花一倍成本,不愿意为"免费但越改越差"继续买单。

## 11. 风险与兜底

| 风险                           | 兜底                                                                 |
| ------------------------------ | -------------------------------------------------------------------- |
| 外部检测器限流/下线            | 校准层降级为"仅内部信号",UI 标注"离线校准模式"                      |
| 本地 PPL 模型与主流检测器偏差大 | 定期重标定;Spearman < 0.6 时**禁止对外展示分数**,只展示风险色块    |
| 改完仍降不下来                 | 显式告诉用户 `ai_score_final ≥ target`,给出"已尽力"报告而非伪装成功 |
| 事实被改                       | Validator 硬门拦截;违规 → 回退原句;不信任 LLM 自证                 |
| Best-of-N 成本飙升             | 对长文本启用"只改 top-K 高分句",低分句零成本                        |

## 12. 落地路线(分期)

### P0(1~2 周)— 止血 + 建度量

- 前端把 `AI率` 改名为"启发式风险分",加 tooltip 明确说明。
- 实现 `scorer` 包骨架(perplexity + burstiness),上线 A/B 对照。
- 建立 500 条标注集,完成首版校准,相关性 ≥ 0.6 才启用新分数。
- 取消中文硬编码 2 轮,改为"默认 1 轮,可选 2 轮"。

### P1(3~4 周)— 闭环 + 保真

- 实现 Validator 三道门(事实不变量 + SimCSE + 可读性)。
- Coordinator 接入 Best-of-N,句级改写。
- Pipeline 决策循环替换固定轮次,加入 `no_improvement_rounds` 保护。
- 接入第一个外部检测器(建议 Sapling 或 ZeroGPT API,便宜且有 SDK)。

### P2(1~2 月)— 体系化

- 第二/第三个外部检测器 + 投票。
- 用户投诉样本回流管线,周度自动重标定。
- 用户可视化:雷达图 + 参考检测器 + 校准相关性。
- 开放"目标 AI 率"滑块(高级用户可设 0.20~0.40)。

---

## 13. 明确不做的事

- ❌ 不做**对抗绕过特定检测器**的规则(法律与产品伦理红线)。
- ❌ 不做**不告诉用户就注入不可见字符**的 trick(一查就穿,砸招牌)。
- ❌ 不做**保证 100% 降到某个值**的承诺(任何检测器都在迭代,承诺即翻车)。
- ❌ 不做"更大模型一定更好"的幻想,小模型 + 好闭环胜过大模型 + 瞎改。

---

## 14. 结论

把这三件事做到,才算真正解决"AI 率反而升高"的问题:

1. **度量要真**:内部分对齐真实检测器,而不是自编自算。
2. **目标要准**:句级定位 + 复合损失,而不是整篇胡乱重写。
3. **闭环要硬**:Best-of-N + 保真门控 + 条件终止,而不是固定跑几轮。

任何跳过其中一项的方案,最终都会在用户面前重演"28% → 72%"的翻车。
