# AI-Rate Card Diff Backend v1 Design

## Clarifying Question

1. `aiRate` is ambiguous today because the backend has no probabilistic AI detector, only deterministic quality checks. Proposal: treat `aiRate` as a normalized review-priority proxy, not a classifier probability, and compute it as `failed_checks / total_checks` from the final per-chunk quality result. That keeps the score deterministic, explainable, and derived from existing `Checks` / `QualityReport` data without changing the quality model.

## Proposed API Contract

`GET /sessions/:id/diff?round=N`

```json
{
  "round": 1,
  "chunks": [
    {
      "id": "p0_c0",
      "paragraphIndex": 0,
      "chunkIndex": 0,
      "input": "Original text",
      "output": "Rewritten text",
      "status": "passed",
      "charDelta": 12,
      "aiRate": 0.25,
      "state": "pending",
      "checks": [
        { "type": "empty", "passed": true }
      ]
    }
  ]
}
```


`GET /sessions/:id/export?round=N&format=txt|docx&selection=all|accepted`

- `selection=all` remains the default to preserve current behaviour.
- `selection=all`: `accepted` and `pending` export rewritten text, `rejected` exports original text.
- `selection=accepted`: only `accepted` exports rewritten text; `pending` and `rejected` export original text.
- Invalid `format` or `selection` returns `400`.
- Unknown `session`, `round`, or `cardId` returns the existing not-found style error.

## Data Model Deltas

- Add `ChunkReviewState` as a new string enum:
  - `pending`
  - `accepted`
  - `rejected`
- Extend `domain.Chunk` because manifest persistence stores `[]Chunk`:
  - `AIRate float64  json:"ai_rate,omitempty"`
  - `State  ChunkReviewState json:"state,omitempty"`
- Extend `domain.ChunkDiff`:
  - `AIRate float64         json:"aiRate"`
  - `State  ChunkReviewState json:"state"`
- Keep existing `/diff` fields unchanged; only append `aiRate` and `state`.
- Defaulting rules for old manifests:
  - missing `state` or empty string => normalize to `pending`
  - missing `aiRate` => keep `0`

## Persistence And Migration

- No SQL migration is required because manifests already store chunks as JSONB.
- New manifests will persist `AIRate` and `State` inside each chunk JSON object.
- Old manifests deserialize cleanly; service logic must normalize empty state to `pending` before diff/card/export logic runs.
- To support accept/reject mutations, extend `ManifestRepository` with an upsert-style save method so service code can persist the mutated manifest without going through `RoundRepository.CompleteRound`.

## Service And Handler Changes

- Add service methods:
  - `ListCards(ctx, sessionID, roundNumber)`
  - `AcceptCard(ctx, sessionID, roundNumber, cardID)`
  - `RejectCard(ctx, sessionID, roundNumber, cardID)`
  - `ApplyAllCards(ctx, sessionID, roundNumber)`
- Reuse `ChunkDiff.ID` as `cardId`; no new identifier layer.
- Card mutations load the round manifest, normalize states, mutate the matching chunk, then save the manifest.
- Use the existing session advisory lock around manifest mutations to avoid last-write-wins races between concurrent review actions.
- Add handler methods and routes:
  - `GET  /sessions/:id/cards`
  - `POST /sessions/:id/cards/:cardId/accept`
  - `POST /sessions/:id/cards/:cardId/reject`
  - `POST /sessions/:id/cards/apply-all`

## Export Selection Logic

- Do not export from `round.OutputPath` anymore when `selection` is requested, because that file is always the fully rewritten text and cannot honor rejected chunks.
- Build export text from the manifest instead:
  - iterate paragraph mappings in order
  - for each chunk ID, choose either `chunk.Output` or `chunk.Text` based on `selection` and `state`
  - join chunk parts with the same separator used by `merge` today
  - join paragraphs with `\n\n`
- Safety fallback: if a chunk has no rewrite text, export original text regardless of `selection`.
- Feed the selected text into the existing exporter so TXT and DOCX keep the current fidelity ceiling.

## Implementation Notes

- `aiRate` should be computed once when the final manifest is assembled, from the final `QualityReport`, then persisted on the chunk so `/diff`, `/cards`, and export do not need extra `quality_reports` queries.
- `apply-all` should update only chunks still in `pending` state; already accepted or rejected chunks stay unchanged.
- Pending state is a review-state default, not a processing-state default. It does not affect chunk `status`.
