## 1. Product intent

The customer wants a card-based review flow on top of the existing per-chunk diff.
Each card represents a text chunk flagged as likely AI-written. The user accepts or
rejects rewrites individually, or hits "apply all" to accept everything pending.
Only accepted rewrites flow into the exported document; rejected chunks keep the
original text. Formatting must not drift relative to what we export today.

## 2. Current state (verified, 2026-04-18)

- Module: `github.com/iwen-conf/Naturalize` (Go 1.26).
- Chunk diff model: `internal/domain/chunk.go` — `ChunkDiff{Input, Output, Status, Checks, ...}`.
- Round diff exposure: `GET /sessions/:id/diff?round=N` → `service.ReadDiff` → `domain.RoundDiff`.
- Export path: `GET /sessions/:id/export?round=N&format=txt|docx` → `service.Export` → `nodes.Exporter.Export`.
- DOCX export today is generated from the **rewritten plain text**: every paragraph becomes a single `<w:r><w:t>` run inside `<w:p>`; original upload formatting is not retained. This sets the fidelity ceiling for v1 — see §6.
- Quality gate score lives on `ChunkResult.Checks` / `QualityReport`; an AI-rate-style numeric score is not yet surfaced on `ChunkDiff`.
- Manifest persistence: `internal/infra/postgres/session_repo.go` (`ManifestRepository`). Diff data already round-trips through manifest JSON.

## 3. Scope (v1)

In scope:
1. Surface an AI-rate score on every `ChunkDiff`.
2. Persist a per-chunk review `state ∈ {pending, accepted, rejected}` in the manifest and expose it through the diff/card APIs.
3. Add card endpoints for listing, accept/reject, and bulk apply-all.
4. Teach `Export` to honour per-chunk state: accepted → rewrite, rejected → original, pending → treat as **accepted by default** (consistent with "apply all" intent); make the default configurable via a query flag so the frontend can switch to "only accepted" once the UI lands.
5. Tests: unit-level for handlers, service, and export selection logic. Reuse existing test patterns in the same packages.

Out of scope (do not implement):
- Frontend card UI, SSE for card events, polling is fine for v1.
- Run-level preservation of the **original upload's** docx formatting. Our current export already regenerates docx from plain text; we do not have the original `word/document.xml` retained per session. If you want to propose a phase-2 plan for retaining the upload's run structure, put it in the design note, do not code it.
- Changing the quality-gate model. Reuse what it already produces.

## 4. API contract

You own the contract. Publish it inside your delivery (see §9). Keep it stable
enough that a separate frontend can be built against it without re-reading code.
A reasonable starting point — feel free to refine:

```
GET  /sessions/:id/cards?round=N
  → { round, cards: [ { id, chunkIndex, paragraphIndex, original, rewrite, aiRate, state, status, checks } ] }

POST /sessions/:id/cards/:cardId/accept?round=N      → { card }
POST /sessions/:id/cards/:cardId/reject?round=N      → { card }
POST /sessions/:id/cards/apply-all?round=N           → { updated: int, cards: [...] }

GET  /sessions/:id/export?round=N&format=txt|docx&selection=accepted|all
  (extend existing handler; default selection = all to preserve current behaviour)
```

Reuse existing id conventions: `cardId` can be the existing `ChunkDiff.ID` — no new ids unless justified.

## 5. Data model deltas

- Extend `domain.ChunkDiff` with:
  - `AIRate float64 \`json:"aiRate"\`` — normalised 0..1 score derived from `Checks` / quality report. Document how it is computed.
  - `State ChunkReviewState \`json:"state"\`` — new enum `pending|accepted|rejected`. Default `pending`.
- Persist `AIRate` and `State` via `ManifestRepository`. Migrate gracefully when old manifests lack the fields (treat missing state as `pending`, missing rate as `0`).
- Do not break the current `/sessions/:id/diff` shape: add the new fields, keep existing ones.

## 6. Export behaviour

- `service.Export` must accept a selection mode. For each chunk, pick the text per §3.4.
- Reassemble paragraphs in the same order as `manifest.Chunks`. Preserve the current paragraph-per-newline-pair convention used by `nodes.buildDocumentXML`.
- TXT export: same reassembly, plain text.
- Do not alter `buildDocumentXML` beyond what is required to accept pre-assembled text; keep the existing styles/content-types unchanged.
